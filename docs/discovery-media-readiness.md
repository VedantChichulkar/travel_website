## Architecture

The manifest remains the code-curated fallback layer for the verified V1 dataset. Administrator-uploaded destination and place images are now stored in the separate `public_media_assets` registry with entity identity, immutable rights provenance, specificity, alt text, dimensions, replacement history, and an opaque public storage key. It is deliberately not a generic media CMS.

The customer UI resolves media through `frontend/src/lib/discovery-media.ts`:

1. approved `SPECIFIC` entity asset;
2. the entity's declared Interest asset, rendered as `FALLBACK`;
3. the global Maharashtra Tourist Places discovery fallback;
4. a non-image Maharashtra Tourist Places tile if both files fail at runtime.

An `image_url` alone is not sufficient to promote an image to `SPECIFIC`. Curated assets require the matching manifest record; administrator uploads require a complete database rights record and an explicit exact-subject confirmation. This prevents an unknown remote URL from silently becoming customer-facing media.

The resolver owns the public asset reference, so a future local-to-CDN/object-storage move changes manifest values rather than every card and detail component. This public discovery system remains separate from private identity, KYC, and operational document storage.

## Status and rights rules

- `SPECIFIC`: the asset genuinely depicts the named subject and has an approved usage basis.
- `EDITORIAL`: atmospheric or illustrative media that does not claim to document a named subject.
- `FALLBACK`: a deterministic category or global substitute for an entity without approved specific media.

Current local artwork is recorded as generated by the Maharashtra Tourist Places editorial asset pipeline for project use. It is non-documentary. Generated artwork may support Interest heroes, atmosphere, and fallbacks, but must never be described as a photograph of an event, person, community, monument, reserve, or beach.

## Replacing a Place or Story fallback

1. Acquire an owned, commissioned, officially reusable, or appropriately licensed asset. Do not scrape search results, tourism blogs, social platforms, or watermarked images.
2. Retain the original acquisition record outside the public bundle when contracts or source files require it.
3. Add a production derivative under `frontend/public/images/discovery/` or upload it to the approved public-media origin.
4. Add or reuse a provenance record with source, creator, usage basis, licence, attribution, source URL, verification date, and documentary status.
5. Update the canonical Place (`district/slug`) or Story (`slug`) manifest entry with `asset`, `alt`, `provenanceId`, and `status: "SPECIFIC"`.
6. Update the curated backend `image_url` only when the dataset should expose that public reference. Both layers must agree.
7. Run `npm run test:media`, the backend media-manifest tests, lint, type-check, build, and browser QA.

## Alt-text policy

- Specific documentary media describes only what is visibly shown.
- Editorial Interest media begins with a clear generic/generated editorial description.
- Entity fallbacks state that they are category fallbacks and do not depict the subject.
- Decorative overlays and gradients use no alt text or are hidden from assistive technology.
- Names and tourism keywords are not repeated for search-engine stuffing.

## Content-quality audit

All 49 Place short descriptions and descriptions and all 10 Story summaries and bodies were reviewed for duplication, unsupported superlatives, formulaic tourism language, district naming, historical naming, cultural sensitivity, and verbosity. No factual enrichment was added. Existing canonical forms—Devgiri-Daulatabad Fort, Chhatrapati Sambhajinagar, Alibag Beach, Pench Tiger Reserve, Maharashtra, Shri Vitthal-Rukmini Temple, Takht Sachkhand Sri Hazur Sahib, and Ganpatipule Beach and Temple—remain supported and their slugs remain stable. No concrete defect justified rewriting verified copy.

## Performance and operational notes

- Above-fold hero media uses eager/high-priority loading; cards remain lazy.
- Cards and details provide fixed-height or aspect-ratio containers to prevent layout shift.
- Responsive `sizes` are set by usage context.
- Five multi-megabyte editorial PNGs and four reused Interest-hero PNGs now have non-destructive WebP derivatives. Originals remain untouched.
- Search remains text-only; thumbnails were not added.
- This is not a media CMS. The current volume is better served by reviewed code changes and manifest validation.
